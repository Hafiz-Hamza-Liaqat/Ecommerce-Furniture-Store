# RC10.3 — Compatibility Verification

**Status:** Implemented — awaiting manual review  
**Date:** 2026-07-21

## APIs

| Function | Behavior |
|----------|----------|
| `deriveCompatibleCategories(role)` | Keywords from role slugs + name cues (office chairs, dining, school, medical, bedroom, lounge, storage, tables, …) |
| `isProductCompatible(product, role)` | Rejects obvious mismatches; then accepts slug overlap **or** category/tag/name match against derived categories |

Mismatch guards block category bleed that slug overlap alone might allow (e.g. dining on an office-chair role).

## Example — office chair vs dining

| Check | Result |
|-------|--------|
| Role: Executive chair (office template) | Derived: office / executive / ergonomic / task / visitor / conference chairs, workspace |
| Product: dining chair (`spine-dining-chair` / `cove-dining-chair`) | `isProductCompatible` → **false** (dining mismatch) |
| Product: office/task chair (`focus-task-chair` / `boardroom-chair`) | `isProductCompatible` → **true** |

Covered by `rc103-configurator.test.ts` (“rejects dining chairs for an office / executive chair role”).

## Alternatives drawer

`listCompatibleAlternatives` only returns catalogue products that pass `isProductCompatible` for the line’s role. Preferences soft-rank; they do not widen the hard gate.
