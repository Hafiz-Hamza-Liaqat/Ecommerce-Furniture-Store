# RC10.8 Phase 4 — API Inventory

Date: 2026-07-21  
API version: `v1`  
Service: `afh-api` `0.1.0`

## Inventory result

The runtime exposes 20 concrete HTTP operations across 19 paths. Business modules do not expose separate REST resources: they use the authenticated CQRS gateways `POST /api/v1/commands` and `POST /api/v1/queries`. Planner, configurator, most marketing analytics, AI consultant, and some generic ERP screens are browser-local consumers and do not add HTTP endpoints.

All JSON success/error responses use `application/json; charset=utf-8`. Protected operations require `Authorization: Bearer <opaque-session-id>`. Tenant-aware CQRS requests additionally bind the authenticated company through `x-company-id` and the payload `companyId`. Errors use:

```text
{ "error": { "code", "category", "message", "details", "retryable", "correlationId" } }
```

Command/query successes use:

```text
{ "ok": true, "data": <handler result>, "correlationId": <uuid> }
```

`OPTIONS` is handled centrally for CORS preflight. Known paths now return `405 method_not_allowed` and an `Allow` header. Non-empty `POST`, `PUT`, and `PATCH` bodies require `application/json`; other media types return `415 unsupported_media_type`. The body ceiling is 1,048,576 bytes and excess input returns a complete `413 payload_too_large` response.

## Shared CQRS schema rules

- Create/update payloads require `companyId`; resource identifiers are module-specific (`projectId`, `customerId`, `salesOrderId`, `leadId`, and so on).
- `Get*` queries require `companyId` plus the resource identifier.
- `List*` queries use `{companyId,q?,criteria?}`. Offset paging is `criteria.page={page,pageSize}`; cursor paging is `criteria.page={cursor,limit}`. The default page size is 50 and the hard maximum is 500.
- List responses use `{items,totalCount,page,pageSize,nextCursor,hasMore}` after authorization filtering.
- Unknown command/query types return `404`; validation failures return `400`; Policy denial and tenant mismatch return `403`; missing records return `404`; conflicts use `409`.
- Client-supplied owner, organization, branch, company, restricted finance, and KYC fields remain subject to handler scope binding and field authorization.

## Seed and environment dependencies

- Development authentication and broad CQRS verification use the seeded `admin@afh.local` account and `company-demo`.
- Production-profile protocol checks use a clean production database and do not rely on a seeded user.
- CRUD commands can require registered workflow definitions, Policy catalog/role assignments, related customer/product records, inventory, or accounting references. Tests use generated records where possible and module fixtures otherwise.
- Planner, configurator, AI consultant, and browser-local ERP fixtures have no server contract to inventory. Their persistence contracts are local storage/CX synchronization and were covered in Phases 1–3.
