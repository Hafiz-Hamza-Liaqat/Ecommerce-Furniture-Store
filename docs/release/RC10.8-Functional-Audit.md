## Confirmed defect

### P2-D1 — ERP required fields could be bypassed

- Route: `/app/sales/customers/new` (shared by generic ERP forms)
- Workflow: ERP create validation
- Severity: High
- Steps to reproduce:
  1. Sign in as administrator.
  2. Open a generic ERP create route.
  3. Clear a field marked required.
  4. Submit.
- Expected: Submission remains on the create route and explains which required
  field is missing.
- Actual: A local/API-backed record could be created because `FormShell`
  disables native validation and `ModuleApp` did not validate required fields.
- Evidence: Initial Phase 2 harness failure:
  `Sales: missing required value unexpectedly created a record`.
- Root cause: `ModuleApp` built `permittedValues` and entered create/update
  handling without checking `visibleFields[].required`.
- Fix: Before mutation, filter visible/editable required fields whose values are
  empty after trimming; display `Complete required fields: …`; clear submitting
  state; return.
- Targeted validation:
  - ERP targeted tests: 7/7 PASS
  - Web typecheck: PASS
  - Phase 2 full harness after fix: 21/21 PASS
- Regression validation:
  - Web suite: 216/216 PASS
  - Monorepo typecheck: PASS
  - Monorepo lint: PASS
  - Production build: PASS
  - Playwright suite: 16/16 PASS

No other product defect met the reproduce-and-fix threshold.

- **R2 (A)** — The implemented credential-rotation path is the reset flow,

  never part of RC10 scope.
- **R3 (C, completed)** — MFA is implemented, user-reachable, and
  security-relevant, but had neither browser nor service-level end-to-end
  coverage; that combination made it a genuine functional gap. Completed as a
  Phase 2 extension using a disposable activated account.
- **R4 (A)** — `service.ts` contains no payment mutation; `paymentStatus` is

- **R5 (A)** — Delivery state is derived from order status by design; the

- **R6 (A)** — The generic Export action is intentionally presentation-level
  for entities without server bulk export; the API-supported exports are
  covered by API tests and the frozen-contract suite.
- **R7 (A)** — No delete API exists for opportunities; retaining pipeline
  history is an intentional audit-trail decision.
- **R8 (A)** — The CX workspace and generic ERP modules are deliberately
  parallel stores in RC10; both were verified independently.
- **R9 (B)** — Sealed-by-default challenge responses are verified by API unit

  production provider.
