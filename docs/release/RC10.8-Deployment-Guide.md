# RC10.8 — Deployment Guide

- **Status:** Implemented — awaiting manual acceptance (no commit / push / tag)
- **Baseline HEAD:** RC10.7 commit `0a5b9f2`
- **API version:** v1

This guide summarizes the RC10.8 deployment posture. It complements the
operations docs under `docs/operations/` (`startup.md`, `backup-restore.md`,
`disaster-recovery.md`, `env.example`) — those remain the source of truth for
procedures.

## Prerequisites

- Node.js ≥ 20
- Built packages (`npm run build`)
- Required production secrets set (see `docs/operations/env.example`)

## Configuration (production profile)

Set via environment / secret manager — never commit real values:

- `AFH_PROFILE=production`
- `AFH_CORS_ORIGIN=https://app.example.com` — **explicit allowlist**; production
  rejects `*` and fails closed
- Secrets: `AFH_SECRET_JWT_SIGNING_KEY` (≥ 32 chars), `AFH_SECRET_DATABASE_URL`,
  `AFH_SECRET_BROKER_CREDENTIAL`, `AFH_SECRET_API_SECRET`
- Persistent storage paths: `AFH_DATABASE_PATH`, `AFH_BROKER_DATABASE_PATH`; the
  same directory also holds `cx-sync/` and `dam-objects/`
- Keep `AFH_EXPOSE_OPENAPI=false` in staging/production
- `AFH_TRUST_PROXY=true` only behind a trusted reverse proxy

## Startup

1. `npm run start -w @afh/runtime-host`
2. Confirm logs show `Startup validation passed` and `api.host.started`
3. Verify health probes (17) and readiness
4. Startup fails closed on invalid configuration, secrets, migrations, broker,
   or any `down` health probe

## Backup, restore & DR

- Use `scripts/backup-sqlite.sh`. It uses `sqlite3 .backup` when available and
  includes `cx-sync/` and `dam-objects/`. If `sqlite3` is unavailable, stop the
  runtime before copying (WAL writes make plain copies unsafe).
- Backup set is one consistency unit: application SQLite, broker SQLite,
  `cx-sync/`, `dam-objects/`.
- Restore and DR procedures: `docs/operations/backup-restore.md` and
  `docs/operations/disaster-recovery.md`.
- Root `.gitignore` excludes runtime data (DBs, WAL/SHM, `cx-sync/`,
  `dam-objects/`, `backups/`).

## Tagging & versioning

- Recommend an **annotated `rc10.8` tag — only after manual approval**. Do not
  auto-tag.
- **Do not bump package versions** (root `0.0.0`, packages `0.1.0` historical
  scheme). API remains **v1**.
