## Defects found

### D1 — CSP `frame-ancestors` in HTML meta (systemic console error)

| Field | Detail |
|-------|--------|
| **Severity** | Medium (noise + misleading security signal) |
| **Evidence** | 170× per initial run: `The Content Security Policy directive 'frame-ancestors' is ignored when delivered via a <meta> element.` on every route |
| **Root cause** | `frame-ancestors` is response-header-only; ignored in `<meta http-equiv="Content-Security-Policy">` |
| **Impact** | Console flooded; developers may believe clickjacking protection is active in static HTML when it is not |

### D2 — Record-scoped summary queries called without required IDs

| Field | Detail |
|-------|--------|
| **Severity** | High (real HTTP 400 on dashboard) |
| **Evidence** | `POST /api/v1/queries` → 400 `validation_failed`: `projectId is required` / `serviceRequestId is required` on `/app`, `/app/projects`, `/app/service` |
| **Root cause** | `LiveBackendSummaries`, module dashboards, and analytics packs invoked `projects.GetProjectSummary` and `service.GetServiceSummary` with `{ companyId }` only; API validators require record IDs |
| **Impact** | Executive dashboard live summaries failed silently (caught in UI) but produced console/network errors on every `/app` visit |

### D3 — Login auth links fail WCAG AA contrast

| Field | Detail |
|-------|--------|
| **Severity** | Medium (accessibility) |
| **Evidence** | axe `color-contrast` on `a.auth-card__link` — ratio **4.09:1** (required 4.5:1) |
| **Root cause** | `.nav-link { opacity: 0.85 }` diluted `#7a5f3a` foreground on light card background |
| **Impact** | “Reset password” / “Create account” links hard to read for low-vision users |

### D4 — Nested interactive controls (`role="img"` + buttons)

| Field | Detail |
|-------|--------|
| **Severity** | Medium (accessibility) |
| **Evidence** | axe `nested-interactive` on `.booklet__spread` (home) and `.ws-map` (executive dashboard) |
| **Root cause** | Container marked `role="img"` while containing focusable `<button>` pins / hotspots |
| **Impact** | Screen readers treat interactive controls as decorative |

### D5 — Blocked `fetch` to Google Fonts during audit (harness artifact, not a product defect)

| Field | Detail |
|-------|--------|
| **Severity** | None (audit tooling only) — initially misdiagnosed as a CSP gap |
| **Evidence** | During search interaction: `connect-src` violation + `Couldn't load preload assets: ProgressEvent` warnings |
| **Root cause** | The `fetch()` to `fonts.googleapis.com` was issued by **axe-core's CSSOM preload** (`preloadCssom`, `axe.js:29293`) injected by the audit harness — not by application code. The app loads the stylesheet via `<link rel="stylesheet">` (governed by `style-src`) and font files via `@font-face` (governed by `font-src`); neither uses `connect-src`. |
| **Correct fix** | Harness-side: run axe with `preload: false`. An interim change that added the fonts hosts to `connect-src` was **reverted** as semantically wrong — it widened the page's fetch/XHR surface solely to accommodate a test tool. |

**CSP correctness rationale (final configuration):**

| Resource | Loading mechanism | Governing directive | Policy value |
|----------|-------------------|--------------------|--------------|
| Google Fonts CSS | `<link rel="stylesheet">` | `style-src` | `'self' 'unsafe-inline' https://fonts.googleapis.com` ✅ |
| Font files (woff2) | `@font-face` inside that CSS | `font-src` | `'self' https://fonts.gstatic.com` ✅ |
| fetch/XHR/WebSocket | application code | `connect-src` | `'self'` + local API/HMR hosts only ✅ (no fonts hosts — the app never fetches them programmatically) |

`preconnect` hints are not governed by CSP and remain in place for performance.

## Post-acceptance CSP verification (2026-07-21)

Requested final check on the Google Fonts CSP change:

- **Finding:** the interim addition of fonts hosts to `connect-src` was semantically incorrect. The blocked fetches came from axe-core's CSSOM preload (test tooling), not from application code. Stylesheet and font loading were already correctly covered by `style-src` and `font-src`.
- **Correction applied:** fonts hosts removed from `connect-src` (smallest possible fix); harness already runs axe with `preload: false`.
- **Re-verification:** full Phase 1 audit rerun after the revert — search interaction PASS, 0 CSP/connect-src flags, 0 non-allowlisted console messages on the affected scenario. The only flagged items were the two known timing flakes, both confirmed clean on settled pages (planner: 8 headings; home: 0 contrast violations).
