# RC10.5 — Conflict Resolution

## Detection

A conflict is raised when local and remote revisions for the same key both exceed the last-known cursor revision and payloads differ (e.g. project edited on two devices).

## Resolution (deterministic)

- Compare `revisedAt`; **later timestamp wins**.
- Loser payload archived under `afh.cx.sync.conflict.{key}.{id}` for review.
- `ConflictEvent` recorded in `afh.cx.sync.conflicts` (never silent overwrite without a log).
- Status chip shows **Conflict detected**.

No automatic “last writer wins without audit.”
