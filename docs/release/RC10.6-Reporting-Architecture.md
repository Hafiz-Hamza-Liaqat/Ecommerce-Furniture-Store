# RC10.6 — Reporting Architecture

- **Status:** Implemented — awaiting manual review (no commit)
- **Surface:** `/app/sales/analytics` (Workspace BI)
- **Package:** `packages/web/src/marketing/cx/analytics/`

## Principles

1. Reporting and visibility only — no workflow mutations.
2. Reads existing CX stores (`afh.cx.sales.workspace`, projects index, planner plans, notifications).
3. Separation of concerns: source → filter → metrics → derive → presentation / export.
4. Reuses design-system charts (`workspace/charts`) and `bi-*` / `ws-card` chrome.
5. No third-party BI platform; no accounting / ERP / collaboration integration.

## Layers

| Layer | Module | Responsibility |
|---|---|---|
| Source | `source.ts` | Read-only snapshot adapters |
| Filter | `filter.ts` | Date / salesperson / project / customer / stage / status / style / room / category |
| Metrics | `metrics.ts` | Pure KPI + distribution calculations |
| Derive | `derive.ts` | Compose `BiReport` |
| Export | `export.ts` | CSV download + print-to-PDF |
| UI | `ui/*` | Tabs, filters, KPI cards, charts |

## Extension points (not implemented)

`registerBiExtensionHooks` accepts callbacks for profit analysis, inventory analytics, financial reporting, AI forecasting, and multi-branch reporting — reserved for later releases.
